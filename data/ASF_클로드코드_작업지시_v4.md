## 0. 작업 원칙 (모든 작업에 적용)

1. **코드를 먼저 내밀지 말 것.** 각 단계 시작 전에 "지금 무엇을 / 왜 / 결과가 어디 쓰이는지 / 사용자가 결정할 것"을 먼저 말하고 동의를 받은 뒤 진행한다.
2. **가상 데이터 금지.** 불가피하게 임시값을 쓰면 코드 주석과 출력 양쪽에 명시한다.
3. **등급 판정은 100% 규칙 기반.** LLM은 판정에 절대 관여하지 않는다. LLM 역할은 브리핑 문장 생성뿐.
4. **검증용 데이터와 표시용 데이터를 섞지 않는다.** (3장 참조)
5. 자동 동의 금지. 설계가 이상하면 지적한다.

## 1. 프로젝트 정의

ASF(아프리카돼지열병) 방역 담당 공무원을 위한 도구.
최근 발생 위치를 기준으로 **이번 주 어느 농장을 먼저 점검해야 하는지** 순서를 제시한다.

기존 정부 분류는 시군 단위이면서 **정적**이다. 이 도구는 **시점에 따라 순위가 바뀐다**. 이것이 차별점이다.

**두 층 구조 — 이 프로젝트의 핵심 설계다.**

| 층 | 단위 | 검증 | 화면에서의 역할 |
|---|---|---|---|
| **신호 검증층** | 시군 | 리플레이로 검증 | 지도 색칠 (배경) |
| **적용층** | 농장 | 검증 불가 | 점검 순서 목록 (주 출력) |

"시간축 신호가 유효한가"는 시군 단위로만 검증 가능하다(4.4). 그 신호를 농장 단위로 적용해
실무에 쓰이는 형태로 만든다. **검증된 것과 적용한 것을 문서·화면·발표에서 항상 구분한다.**

산출물 3개:
- 전국 시군 등급 지도 (색칠) + 농장 점 표시
- 시군 클릭 시 우측 패널: 해당 시군 등급 근거 + 농장 점검 순서 목록
- 주간 브리핑 문장 (LLM 생성)

## 4. 확정된 설계

### 4.1 공간 단위 — 시군

- 주소가 리 단위까지라 농장 좌표는 ±수 km 오차. 더 잘게 쪼개도 정밀도가 가짜다
- 농장 위치가 전국 단위로 없어, 리 단위로 가면 분모에 양돈장 없는 리 수만 개가 들어가 검증이 무의미해진다
- 공개 농가수 통계의 최소 단위가 시군이다
- 방역 담당이 시군 단위로 배치돼 있다

### 4.2 등급 규칙

**인자는 거리와 시간, 두 개뿐이다.**

- **신호: 인근 발생 하나만.** 멧돼지 검출은 넣지 않는다 (데이터 미확보 + 검출이 실제 분포가 아닌 수색 활동을 반영하는 편향)
- **기간 3주** (이동제한 기간) — 정부 규정값을 그대로 차용
- **3단계 — 거리로 가른다 (확정):**

| 등급 | 조건 (`as_of` 기준 3주 이내 발생에 대해) |
|---|---|
| **심각** | 발생 지점에서 **10km 이내** — 법정 방역대 |
| **주의** | 발생 지점에서 **10~20km** — 방역대 밖이나 역학 관련 범위 |
| **평시** | 20km 초과 또는 3주 경과 |

- **등급 하강은 시간 경과로 자동.** 별도 해제 규칙 없음
- **거리 계산은 발생 지점 좌표(리 중심점) 기준**, 등급 부여는 시군 단위

#### 등급 인자에 넣지 않는 것 — 이유가 설계의 핵심이다

**사육밀도(2.6)와 재발 이력을 등급 계산에 넣지 말 것.**

둘 다 시군마다 사실상 고정된 값이다. 이를 등급에 넣으면 밀도 높은 시군·과거 발생 시군은
**발생이 없는 주에도 항상 등급이 올라가 있게 된다.** 그러면 지표 B(4.4)가 무너진다 —
파주시가 늘 '주의' 이상이면 비교 대상인 '평시' 주 자체가 사라지기 때문이다.

이 도구의 차별점은 **시간축 신호**다. 지역 고유의 정적 속성을 등급에 섞으면 차별점을
스스로 지우는 것이고, 정부의 기존 정적 분류와 같아진다.

밀도는 **분모로만** 쓴다(4.4). 인자로도 쓰고 분모로도 쓰면 순환 논증이 된다.

또한 이벤트가 82건뿐이므로 인자를 셋 이상으로 늘리면 각 인자의 유효성을 확인할 수 없다.
인자가 둘일 때만 "정부 방역대 범위를 시간축으로 확장했더니 구분력이 생겼다"는
한 문장의 결론이 성립한다.

### 4.3 시간 기준 — `case_date`(확진일) 사용

`published_on`(QIA 게시일)은 발생일 대비 **최소 7일, 중앙값 18.5일, 최대 33일** 늦다.
그러나 방역 공무원은 KAHIS를 통해 확진 당일~익일에 인지한다. 게시일로 거르면 **실사용자가 이미 아는 정보를 가려버리는** 것이 되어 현실보다 도구를 불리하게 만든다.

신고일은 2026년분에만 있고 의심축 신고는 비공개라 전 기간 적용이 불가능하다.

→ **모든 시점 필터는 `case_date` 기준.** `published_on` 조인 작업은 하지 않는다.

### 4.4 리플레이 검증

```
for each 주차 T in 2019-09 ~ 2026-08:
    확진일 <= T 인 발생만으로 전국 시군 등급 산정
    확진일 > T (다음 1주) 발생이 어느 등급 시군에서 났는지 기록
```

- **분모는 "시군-주의 사육두수"**. 각 주차에 각 등급에 속한 시군의 해당 연도 사육두수(2.6)를
  합산하고, 발생 건수를 그 합으로 나눈다. 단위는 **1만 두-주당 발생 건수**
- 시군을 한 개씩 세는 방식(시군-주 개수)은 돼지 3만 두 시군과 3천 두 시군을 동일하게 취급한다.
  두수 가중 분모는 **"발생은 돼지가 많은 곳에서 난다"는 자명한 사실을 통제**하므로,
  그러고도 등급 간 차이가 남으면 그것은 밀도가 아니라 규칙이 잡아낸 것이다
- 연도별 두수를 쓴다. 2019년 주차에는 2019년 값, 2026년 주차에는 2026년 값
- **2019~2025 구간과 2026 구간을 분리해서 낸다** (4.6)
- 등급 산정 함수는 `as_of` 인자를 받는 순수 함수로 작성. 전역 상태·현재시각 참조 금지 (미래 정보 유출 방지)

#### 지표 2개를 모두 산출한다 — 두 번째가 주 지표다

**지표 A (보조): 시군 간 비교.** 전체 시군-주를 등급별로 묶어 발생률 비교.

**지표 B (주 지표): 같은 시군 안의 시점 간 비교.**

```
for each 시군:
    그 시군이 '심각'이었던 주들의 발생률
    그 시군이 '평시'였던 주들의 발생률
    → 두 값을 비교
전 시군에 대해 집계
```

**지표 A만으로는 논증이 성립하지 않는다.** 파주 8건, 포천 7건, 철원 6건처럼 발생이 반복되는
시군은 등급도 높고 발생도 많다. A에서 좋은 결과가 나와도 "위험지역이 위험하다"의 재확인일 뿐,
시간축 신호가 작동한다는 증거가 되지 않는다.

지표 B는 지역 고유 위험도를 상수로 소거하고 **시간축 신호만 남긴다.** 같은 파주시인데
'심각'인 주에 발생이 더 많다면, 그것은 지역 특성이 아니라 규칙이 잡아낸 것이다.

계산은 같은 리플레이 결과를 다르게 묶는 것뿐이므로 추가 실행 비용이 없다.
발표에서 인용하는 수치는 **지표 B**다.

### 4.5 농장 점검 순서 — 정렬 규칙 (점수 아님)

시군 등급이 배경이라면, 사용자가 실제로 보는 주 출력은 농장 목록이다.

**대상:** `as_of` 기준 최근 3주 내 발생지로부터 10km 이내 농장 (시군 등급과 동일 기준값)

**정렬:**
1. 가장 가까운 최근 발생까지의 거리 오름차순
2. 동일 거리대(1km 단위로 버킷) 안에서는 사육두수 내림차순

**가중합 점수를 만들지 말 것.** 거리·경과일·사육두수·재발이력을 가중치로 합산한 점수는
검증할 방법이 없다. 농장 단위 발생 이벤트가 52건뿐이라 어떤 가중치가 옳은지 확인이 불가능하고,
임의 가중치는 근거 없는 정밀함을 가장한다. 정렬 규칙은 각 항목이 독립적으로 정당화된다.

**사육두수를 2순위로 쓰는 근거는 발생 확률이 아니라 피해 규모다.** "감염 가능성이 높다"가
아니라 "터졌을 때 피해가 크다"이므로 가중치를 지어내지 않고도 정당화된다.
발표·화면 문구에서 이 구분을 지킬 것.

**표시 개수는 사용자가 조절한다.** 기본 20곳. "하루치 점검 목록"이라고 부르지 않는다 —
점검관이 하루에 몇 곳을 도는지 우리는 모른다. 동선 최적화는 범위 밖(7장).

**농장 목록에 "등급"을 부여하지 않는다.** 등급은 검증된 시군 층의 용어다. 농장 층에는
거리·두수 같은 사실만 표시한다. 화면 문구도 "위험도 순"이 아니라 "발생지 인근 농장(거리순)".

**농장 데이터가 있는 17개 시군에서만 목록이 나온다.** 나머지 시군은 등급만 표시되고
목록은 비며, 화면에 "농장 데이터 미확보"로 명시한다.

### 4.6 2026년 처리 — 실패가 결론이다

2026년 27건 중 **21건이 사료 매개(IGR-I 유전형)**다. 사료 트럭은 전국을 이동하므로 거리 기반 규칙으로는 원리적으로 잡을 수 없다. IGR-II(멧돼지 유래)는 3건(포천 2, 연천 1).

이는 숨길 결함이 아니라 검증 질문이다. 기대 결과:

> 2019~2025 구간에서는 등급이 구분력을 갖고, 2026 구간에서는 무너진다.
> 원인은 전파 경로가 공간 매개에서 사료 매개로 바뀌었기 때문이다.

**2026 구간 성능이 나쁘게 나오는 것을 고치려 들지 말 것.** 그것이 결과다.

### 4.7 데이터 갱신 계층 — 판정 계층과 분리한다

**갱신은 자동이다.** 사용자가 버튼을 누르거나 명령어를 실행하지 않는다.

```
[갱신 계층]  mafra API  →  마스터 CSV 갱신
                   ↓   (CSV를 통해서만 연결)
[판정 계층]  CSV 로드  →  grade(sigun, as_of)  →  화면
```

**두 계층은 CSV를 통해서만 연결된다.** `grade()`는 CSV를 읽는 순수 함수를 유지하고,
판정 경로 안에서 API를 호출하지 않는다. 판정 함수가 네트워크에 의존하면
리플레이가 재현 불가능해지고 4.4 검증 자체가 무효가 된다.

**갱신 방식: 요청 시 갱신 (on-demand)**

- 앱 시작 시 1회 API 호출 → 마스터 갱신
- 이후 요청이 오면 마지막 갱신 시각을 확인. **6시간 경과 시 재호출**, 아니면 캐시 사용
- **API 실패 시 기존 CSV로 정상 동작하고, 화면에 "마지막 갱신: {시각}"을 표시한다.**
  갱신 실패가 서비스 중단으로 이어지면 안 된다
- 신규 발생만 추가한다. 기존 행을 덮어쓰지 않는다. 중복 판정 키는 `case_date` + `address`
- 갱신 시 "신규 N건 추가"를 로그로 출력

**GitHub Actions 크론은 만들지 않는다.** 크론이 필요했던 목적은 매일 스냅샷을 쌓아
정부의 공개 시점을 실측하는 것이었으나, 4.3에서 확진일 기준으로 확정하면서 그 필요가 없어졌다.
요청 시 갱신으로 항상 최신 상태가 유지되므로 크론은 중복이다.

**mafra API 호출 제약 (실측 확인됨)**

```
http://211.237.50.150:7080/openapi/{키}/xml/Grid_20151204000000000316_1/{시작}/{끝}
```

- 한글 필터(`LKNTS_NM`) 사용 불가 — UTF-8·EUC-KR 퍼센트인코딩 모두 거부됨.
  전체를 받아 클라이언트에서 질병명으로 필터할 것
- 999행/호출 제한 → 페이지네이션 필요
- **비SSL(http, 포트 7080).** Claude Code 실행 환경에서는 호출이 차단될 수 있다.
  그 경우 호출부는 구현하되 실제 동작 검증은 사용자 로컬에서 수행한다
- **이 API는 2026년 27건 중 7건이 누락돼 있다** (보령·당진·김천·홍성 + 보충 3건).
  KAHIS 웹 조회도 같은 피드라 동일하게 누락된다. 갱신을 붙여도 완전하지 않다 — T4 한계 항목

## 6. 작업 순서

### T1. 농장 데이터 통합 — **완료 (8-19)**

산출물 `farms_geocoded.csv` — 2,285행 / 49개 시군 / **좌표 결측 0**.
경기 17개 시군은 경기 파일, 나머지 32개 시군은 개별 파일에서 왔고 중복 없음.
좌표는 전부 한반도 범위(위도 33.2~38.3 / 경도 126.2~129.5) 내.

**후속 작업에서 유의할 것:**
- 동일 좌표 그룹 166개(648행) 존재. 한 주소에 복수 법인이 등록된 실제 구조이므로 병합하지 말 것.
  대신 지도에서 마커가 완전히 겹쳐 농장 수가 실제보다 적어 보인다 → **jitter 또는 클러스터 표시 필수**
- 축종 결측 401행. 사용자가 이미 돼지만 필터링했으므로 무시한다

### T2. 등급 엔진 + 리플레이

- `grade(sigun, as_of) -> {평시|주의|심각}` 순수 함수
- `farm_order(sigun, as_of) -> [농장...]` 정렬 함수 (4.5)
- 4.4의 리플레이 루프
- 출력: **지표 A(시군 간) 표와 지표 B(시군 내 시점 간) 표를 모두 산출.** 각각 2019~2025 / 2026 구간별

**완료 기준:** 표 4개(지표 A/B × 2019~2025 / 2026)가 출력되고, 이벤트 수가 적어 신뢰구간이
넓다는 점이 함께 표시된다. 발표에 쓸 주 수치는 **지표 B, 두수 가중 분모** 기준이다.

조인 검증: 2.6 매핑 적용 후 발생 시군 37개가 전부 통계와 연결되는지 확인하고,
실패가 있으면 경고 출력 후 중단한다.

### T3. LangGraph + FastAPI + 화면

- 노드 3개: 문서 구조화 추출 → 판정(T2 함수 호출) → 브리핑 생성
- **판정 노드는 LLM을 호출하지 않는다.** T2 함수를 그대로 부른다
- 브리핑 노드 프롬프트에 **"주어진 목록의 내용만 문장으로 서술할 것. 목록에 없는 시군을
  언급하거나 순서를 바꾸지 말 것"**을 명시한다. LLM이 판정에 개입하면 설계가 무너진다

**화면 구성 — 좌우 2단**

```
┌─────────────────────────┬──────────────────────┐
│  좌: 전국 지도           │  우: 상세 패널        │
│  - 시군 등급 색칠 3색     │  (시군 클릭 시 갱신)   │
│  - 농장 점 (jitter 처리)  │                      │
│  - 발생 지점 + 10km 원    │  ① 주간 브리핑        │
│  - as_of 날짜 선택        │  ② 시군 등급 + 근거   │
│                          │  ③ 농장 점검 순서     │
└─────────────────────────┴──────────────────────┘
```

- 좌측은 항상 전국이 보인다. 시군을 클릭해도 지도는 전국 유지, 우측만 바뀐다
- 우측 ①은 시군 미선택 시 전국 브리핑, 선택 시 해당 시군 브리핑
- 우측 ②: 등급 / 가장 가까운 최근 발생 / 그 거리 / 경과일
- 우측 ③: 4.5 정렬 규칙 적용. 농장명·주소·거리·사육두수 열. 기본 20행, 개수 조절 가능
- 농장 데이터 없는 32개 시군(발생 시군 중 20개)은 ③이 비고 "농장 데이터 미확보" 표기
- 화면 상단에 **"마지막 갱신: {시각}"** 표시 (4.7)

**갱신 계층 (4.7) 구현**

- `refresh_master()` — mafra API 호출 → 신규 발생만 마스터 CSV에 추가
- 앱 시작 시 1회 + 요청 시 6시간 경과했으면 재호출. 크론 없음
- 실패 시 기존 CSV로 정상 동작. 예외를 삼키지 말고 로그에 남길 것
- **`grade()` 안에서 이 함수를 부르지 않는다.** 판정 계층은 CSV만 읽는다

### T4. 발표 자료

명시해야 할 한계:
- **검증은 시군 단위, 농장 순서는 검증되지 않은 적용이다** (1장 두 층 구조)
- 농장 표시는 49개 시군 한정, 지자체 공개 여부에 따른 선택 편향 있음.
  **2.6 통계로 이 49개 시군이 전국 사육두수의 몇 %인지 계산해 명시할 것** (개수보다 설득력 있음)
- 농장 데이터 기준일자가 시군마다 2018~2026으로 상이

- 사료 매개 경로는 범위 밖. **낮은 등급이 안전을 뜻하지 않음**
